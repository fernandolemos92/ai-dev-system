# DESIGN SYSTEM

## Purpose

Design-system discipline now lives in:

`system/design/DESIGN_SYSTEM_STANDARDS.md`

Use that file when work touches:

- `DESIGN.md`
- visual language
- tokens
- component standards
- UI consistency
- design drift
- screen-level visual quality

## Runtime Specialists

Use:

- `system/agents/design-system.md` for reusable system decisions
- `system/agents/ui.md` for screen-level UI craft and visible-state review
- `system/agents/motion.md` for animation, timing, gestures, reduced-motion, and motion performance
- `system/agents/frontend.md` for implementation architecture and code execution

## Design Workflows

Use:

- `system/design/DESIGN_WORKFLOWS.md` for shape/extract/audit/critique/polish/harden/animate moves
- `system/design/DESIGN_MD_TEMPLATE.md` when creating a project `DESIGN.md`

## Final Rule

Design quality must be contextual, inspectable, and connected to implementation.
